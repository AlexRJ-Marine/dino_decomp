# Playtest feedback — 2026-10-27 (user)

Status: open. Captured verbatim, with likely code areas and the evidence each
fix needs. This is the current player-facing priority list; do not silently
drop items.

## 1. Paths (roads / paths tool)

- Placement "feels different" from retail; the placement rules are not
  established.
- Preview texture is wrong: retail draws a **darker blue, unsegmented**
  preview; a port screenshot shows a different/segmented preview.
- Preview must turn **red** when placement is invalid; the port does not show
  that reliably.
- Hidden path for the user: `OPEN_TRANSPORT -> Road` (ROAD-1). Retail evidence:
  `notes/road-retail-*.png` / x32dbg road sessions (check what exists).

## 2. Camera controls

- Still not like retail (orbit/zoom/pan feel, limits, pivot).
- Existing CAM-1 item; `notes/camera-*.md` and retail captures are the
  evidence base. Need a side-by-side control trace (mouse deltas -> camera
  state) before changing constants.

## 3. Building preview

- Placing a building shows a **white model with no texture**.
- Likely the placed/preview mesh does not bind the building texture (or uses
  the collision/white material). Compare with the single-building placement
  path and the imported `drsBuilding` texture lookup.

## 4. Enclosures / paddocks

- Cannot place enclosures at all.
- Retail shows **blue or red circles** for able/unable, like the path preview.
- Needs the same validity/rule model as paths (perimeter, terrain, collision,
  cost) plus the circle preview renderer.

## 5. Campaign levels start empty

- Retail campaign levels start populated; the port shows missing objects.
- `Cpg04_Save.wld` is the richest sample: version 53, 9 fences, 1 show,
  2 animals, 6 employees, 57 buildings, 20 dinosaurs, 14 roads.
- The port's campaign start (`load_campaign_park`) imports **buildings, roads,
  fences and dinosaurs only**. The `.wld` reader discards shows, animals and
  employees (`read_world_block` in `src/formats/wld.cpp`), so even a perfect
  park load is missing them.
- The campaign simulation save (`build/campaign-autosave.sav`) also carries
  2 food sources (list1) and 6 employees (list2) in its `saDinosaur`-style
  lists; these are the live state behind the `.wld` placement records.
- "Load a save for each campaign level" is only partly the answer: the shipped
  `CpgNN_Save.wld` is the initial world state. The port must import all of its
  object lists, then apply the campaign simulation lists when a campaign save
  is loaded.

## Reproduction data

- Cpg01 is intentionally sparse (1 entrance + 1 road, no dinos).
- Cpg04 is the populated test: `--wld-info` reports 57 buildings, 20 dinos,

- Existing campaign test: `tests/test_campaign_cpp.py::test_cpp_menu_campaign_mission_start`
  asserts buildings/dinos but not shows/animals/employees — extend it once the
  import exists.

# Playtest feedback — 2026-10-27 (user)

Status: open. Captured verbatim, with likely code areas and the evidence each
fix needs. This is the current player-facing priority list; do not silently
drop items.

## 1. Paths (roads / paths tool)

- Placement "feels different" from retail; the placement rules are not
  established.
- Preview texture is wrong: retail draws a **darker blue, unsegmented**
  preview; a port screenshot shows a different/segmented preview.
- Preview must turn **red** when placement is invalid; the port does not show
  that reliably.
- Hidden path for the user: `OPEN_TRANSPORT -> Road` (ROAD-1). Retail evidence:
  `notes/road-retail-*.png` / x32dbg road sessions (check what exists).

## 2. Camera controls

- Still not like retail (orbit/zoom/pan feel, limits, pivot).
- Existing CAM-1 item; `notes/camera-*.md` and retail captures are the
  evidence base. Need a side-by-side control trace (mouse deltas -> camera
  state) before changing constants.

## 3. Building preview

- Placing a building shows a **white model with no texture**.
- Likely the placed/preview mesh does not bind the building texture (or uses
  the collision/white material). Compare with the single-building placement
  path and the imported `drsBuilding` texture lookup.

## 4. Enclosures / paddocks

- Cannot place enclosures at all.
- Retail shows **blue or red circles** for able/unable, like the path preview.
- Needs the same validity/rule model as paths (perimeter, terrain, collision,
  cost) plus the circle preview renderer.

## 5. Campaign levels start empty

- Retail campaign levels start populated; the port shows missing objects.
- `Cpg04_Save.wld` is the richest sample: version 53, 9 fences, 1 show,
  2 animals, 6 employees, 57 buildings, 20 dinosaurs, 14 roads.
- The port's campaign start (`load_campaign_park`) imports **buildings, roads,
  fences and dinosaurs only**. The `.wld` reader discards shows, animals and
  employees (`read_world_block` in `src/formats/wld.cpp`), so even a perfect
  park load is missing them.
- The campaign simulation save (`build/campaign-autosave.sav`) also carries
  2 food sources (list1) and 6 employees (list2) in its `saDinosaur`-style
  lists; these are the live state behind the `.wld` placement records.
- "Load a save for each campaign level" is only partly the answer: the shipped
  `CpgNN_Save.wld` is the initial world state. The port must import all of its
  object lists, then apply the campaign simulation lists when a campaign save
  is loaded.

## Reproduction data

- Cpg01 is intentionally sparse (1 entrance + 1 road, no dinos).
- Cpg04 is the populated test: `--wld-info` reports 57 buildings, 20 dinos,
  14 roads, 9 fences, 1 show, 2 animals, 6 employees.
- Existing campaign test: `tests/test_campaign_cpp.py::test_cpp_menu_campaign_mission_start`
  asserts buildings/dinos but not shows/animals/employees — extend it once the
  import exists.

## Suggested queue split

- Port lane: path preview + validity rules, camera parity, building texture,
  enclosure placement (all `src/viewer/main.cpp`, `src/ui/*`).
- Formats/save lane: retain shows/animals/employees in `WldWorld`, expose
  campaign list1/list2, then wire the import; extend the campaign start test.
- Recon: retail path preview color/segmentation and enclosure circle rules
  need screenshots + runtime traces before constants are changed.

## Updates

- 2026-10-27 building preview: diagnosed. `is_static_lod1()` excluded
  `"construction"` but not the retail abbreviation `"construc"`, so stands
  selected `stand_construc_lod1.mesh` (an untextured construction model)
  instead of the normal `standkute_lod1.skin`. The filter now excludes
  `construc`/`crach`, and the Cpg04 import test asserts no construction mesh
  is selected.
- 2026-10-27 campaign population: `WldWorld.records` now retains the `.wld`
  show/animal/employee records; `notes/campaign-world-instantiation.md` is
  being written to resolve the initial positions/profiles/show mapping before
  wiring import.

- 2026-10-27 campaign baseline: Cpg04 through the real menu DOES import 57
  buildings and 20 dinosaurs (`notes/harness/cpg04-campaign.png`; log
  `wld: placed 57/57`, `dinos: 20/20`, `paddocks: 9`). The missing objects are
  the world-block shows/animals/employees (1/2/6), not the buildings/dinos.
  Cpg01/06/08 are intentionally sparse (1 entrance + 1 road, no dinos), so
  they are not evidence of a load failure.

- 2026-10-27 building textures (second cause): the texture directory was
  taken from any `DATA\...` tail string. For most buildings that is a mesh/
  skeleton path, so `souvkute.tga` was looked up inside
  `...souv_construction_lod1.skel/`; only `PointOfView.bbi` really declares a
  texture directory. The code now accepts only a `DATA\...textures...` tail
  string and otherwise uses `Data/Graphics/Textures/buildings`. Cpg04 import
  now reports zero `building texture: cannot open` errors and every one of the
  57 buildings logs its texture name; the test asserts both.

- 2026-10-28 campaign population (first slice): the `.wld` simulation lists
  are now parsed. Cpg04's 6 employees spawn at their saved positions and
  render (`campaign employees: spawned=6/6`, `rendered=6`); their profile is
  0 = Nutritionist, as retail's load path never writes `drsEmployee+0x20`.
  The 2 food sources are parsed (ids 264/267 at 461.5,421.5 / 461.5,445.5)
  but not yet rendered into the food-source GPU list. The show arena/71
  features are the remaining visual piece.

- 2026-10-28 follow-up: both food sources are now spawned and added to the
  AI food list (`campaign food sources: spawned=2/2`); the first one's mesh
  is loaded into the existing single-food draw slot. The renderer currently

- 2026-10-28 visual: `notes/campaign-populated.png` shows Cpg04 after the

- 2026-10-28 camera: reverse-engineered. The retail park camera has **no roll**;
  the motion lean is a pitch transient from one `progress` p plus a 10/s yaw
  low-pass. The interactive camera now uses the retail model
  (`r=10+290p`, `h=3+497p`, `pitch=atan2(h,r)`, zoom == Shift+Up/Down), with
  explicit `--camera-target/--distance` views kept on the legacy spherical
  orbit for deterministic tests. Compare the in-hand feel next; the model is
  no longer a guess (`notes/camera-motion-tilt-recon.md`).

  The strip is unsegmented now; the exact retail blue/alpha still needs the
  harness pixel capture before changing the blend equation.
